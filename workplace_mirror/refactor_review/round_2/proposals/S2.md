## 4. Q-14 (b) partition floor

`build_liquidity_signals(..., model_id, *, crx_persona)` takes the `crx_persona` params
(`"crx_persona": "params:crx_persona"` added to the node's inputs dict in `a1_ability/pipeline.py`;
no catalog or param key renamed). The legs are filtered to
`month_end >= window_start(CASA_HELD_MONTHS, persona_start_date)` and the card payments to
`window_start(W, persona_start_date)`: no new Spark action (income and distress keep
`lookback_floor`). The filter sits on the source before `scoped` and the join, so the three tables'
older months leave before the shuffle (and reach the scan if the dataset is partitioned).

**Can the floor change a value? No.** `_obs_base` keeps only spine rows from the persona start month
on (`_common.py`, `_obs_base`; CC and RL share it), so every observation date >= the start month.
`window_agg` already keeps a row only if `month_end >= window_start(months)` of its own observation,
which is >= the floor (legs use months = 12 for every aggregate, `casa_m1..m{2W}` need <= 12; card
payments use W). So the floor removes only rows no window could read. Nothing was stopped; there is
no case of old data being read today. The A1 spec calls the builder with `PERSONA` by keyword
(`crx_persona=PERSONA`); the signature has `*` so six parameters stay at five positional (pylint
R0917). Workplace tests that call `build_liquidity_signals` positionally need the new keyword.
