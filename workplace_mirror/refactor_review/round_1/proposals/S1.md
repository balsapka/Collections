### S1-07  Episode anchor on the A4 engine: `_dpd_journey.episode_start`
Files: _dpd_journey/anchor.py (new) · _dpd_journey/__init__.py:46,56
Behaviour: none (new function; no tier-L caller).
Change: D-A3-2 says the anchor is the latest spell start as of the observation date, taken from
the A4 engine's `months_before_spell`. A4 already writes, per scored spine row, the episode's
offset into the truncated history (`months_before_spell`) and that history's length
(`history_months`, dense monthly grid ending at the row's month). So the episode's first month is
`add_months(trunc(observation_date, month), -(history_months - 1 - months_before_spell))`.
`episode_start(obs_base, deterioration)` computes it on `crx_<p>_a4_deterioration` and brings it

CC `account_id` is a long, the obs base's is a string). It also carries A4's `left_censored` as
`episode_left_censored` (the episode already ran in the first month A4 used: floor or truncation),
which A3 needs for the D-A3-10 floor measurement. It lives in `_dpd_journey` because the
arithmetic depends on A4's grid; A3 imports it, it never reaches into A4 internals.
Caller count: one function caller today, the A3 engine (CC and RL pipelines). PLAN §2 names this
helper explicitly as one to put in the shared layer in this refactor; under the two-caller rule
it would instead go to the A3 handoff unchanged (`a3_credibility/` would hold the same code).
The Master should decide which rule wins; my recommendation is to ship it here, because a second
copy of the anchor in A3 is exactly the "duplicated anchor logic" all three rubrics block on.

+def episode_start(obs_base: DataFrame, deterioration: DataFrame) -> DataFrame:
+    """``GRAIN + episode_start, episode_left_censored`` for the base rows A4 scored in
+    the observation month.

+    from the latest A4 row on or before the observation date in that month (CC: a
+    billing date). ``episode_left_censored`` is A4's ``left_censored``: the episode
+    already ran in the first month A4 used (history floor, truncation), so the true
+    onset may be earlier. Base rows A4 did not score get no row.
+    """

+        "crx_<product>_a4_deterioration",

The target is the A1 / A2 shape: one engine package (`signals` → `classify`, one `pipeline`
factory taking `product`) on the obs base, and per-product wrappers that hold only what really
differs. For A3 that is the source of dues and payments (CC Way4 statements and card payments; RL
`int_loan_master` EMI and monthly cash). Everything else, including the ledger, is written once.

## Questions (for `questions.md`)

Q-S1-1 [A3 · _dpd_journey/anchor.py (S1-07)] Which date is the episode anchor?
Now: today's A3 `t0` is the first delinquent observation date of the spell (`cc_spell` t0 = first
billing date with DLQ ≥ 2; RL = that month end). A4's output has month indices only, so
`episode_start` gives the first day of the spell's first month. | Spec: D-A3-2 says "latest spell
start", no day.
Options: (a) first day of the month (as written): DCORE contacts and payments earlier in the
first delinquent month count; (b) last day of that month (RL t0 today; CC a few weeks later than
t0); (c) the exact first delinquent statement date, via one more join to `crx_cc_full_history`.
Recommendation: (a), it is the closest to the real onset on both products and needs no join. |
Impact: only the first episode month's DCORE / payment rows; measurable in the A3 bundle check as
old-t0 vs new-anchor crosstab.

Q-S1-2 [A3 · _dpd_journey/anchor.py (S1-07)] Obs-base rows A4 does not score get no anchor.
Now: A4 drops rows whose history is not `ok` (dropped gap, no valid rows) and rows outside the
account's A4 window; with the CC floor (2024-01) an episode that began earlier is left-censored
and starts at the floor month. | Expected: D-A3-2 assumes every scored row has an anchor.
Options: (a) no anchor = A3 Unknown with a reason (`no_episode`); (b) fall back to
`window_start(window_months)` (no episode bound); (c) fall back to the A4 history's first month.
Recommendation: (a), visible in the output and counted in the bundle check. | Impact: A4's
`build_status != 'ok'` share per model_id (in A4's opt-in sequence stats).

Q-S1-3 [A3 · windows] Day-based vs calendar-month window bounds.
Now: A3 writes windows as `observation_date − N months`. Exclusive starts (`> add_months(obs,
−N)`, today's Dimension B) equal `>= window_start(N)` exactly at month-end observations; inclusive
ones (`>= add_months(obs, −12)`, the commitments window, D-A3-9) include one extra day, the last
day of month m−12. | Spec: D-A3-9 "`[max(latest spell start, obs − 12 m), obs]`".
Options: (a) use `window_start` everywhere (calendar months, as A1 / A2); (b) keep day arithmetic
for the commitments window. Recommendation: (a), one window convention across axes; the A3 rebuild
is not a no-change refactor anyway. | Impact: instalments due exactly on that day; tiny.

+"""The episode anchor: the month the current delinquency episode began, point in time.
+
+A4 scores each spine row on the account's monthly history up to that row's month; the
+episode (spell) is the last run of delinquent months in it (a cure back to current ends
+one) and starts ``months_before_spell`` months into that history. Axes that window on
+the episode read its start here instead of from a spell table.
+"""
+
+from __future__ import annotations
+
+from pyspark.sql import DataFrame
+from pyspark.sql import functions as F
+
+from .._common import GRAIN, pit_latest, require_columns, string_key
+
+# The A4 row read is the latest one in the observation's own month.
+_A4_MAX_AGE_M = 1
+
+
+def episode_start(obs_base: DataFrame, deterioration: DataFrame) -> DataFrame:
+    """``GRAIN + episode_start, episode_left_censored`` for the base rows A4 scored in
+    the observation month.
+
+    ``episode_start`` is the first day of the month the current episode began, taken
+    from the latest A4 row on or before the observation date in that month (CC: a
+    billing date). ``episode_left_censored`` is A4's ``left_censored``: the episode
+    already ran in the first month A4 used (history floor, truncation), so the true
+    onset may be earlier. Base rows A4 did not score get no row.
+    """
+    require_columns(
+        deterioration,
+        [*GRAIN, "months_before_spell", "history_months", "left_censored"],
+        "crx_<product>_a4_deterioration",
+    )
+    months_back = F.col("history_months") - 1 - F.col("months_before_spell")
+    src = deterioration.select(
+        string_key(deterioration).alias("account_id"),
+        F.col("observation_date").cast("date").alias("a4_date"),
+        F.add_months(F.trunc("observation_date", "month"), -months_back).alias(
+            "episode_start"
+        ),
+        F.col("left_censored").alias("episode_left_censored"),
+    )
+    return pit_latest(
+        obs_base,
+        src,
+        key="account_id",
+        date_col="a4_date",
+        value_cols=["episode_start", "episode_left_censored"],
+        inclusive=True,
+        max_age_months=_A4_MAX_AGE_M,
+    )
