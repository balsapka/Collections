### S2-01  Scope bank-wide sources to the base's keys before every join; latest-per-key as an aggregate
Files: `_common.py:59-133` (`pit_latest`, `window_agg`; new `scoped`)
Behaviour: none
Change: Every `feat_cif_*_monthly`, `prm_balance`, `int_loan_master` source the helpers join is bank-wide, while the base is one model's customers. Today the sort-merge join shuffles the whole source and only then drops the rows that do not match. `scoped(src, base, key)` left-semi-joins the source against the broadcast distinct keys of the base first (the same pattern `_dcore_events` and `build_way4_deceased` already use), so the shuffle carries only this model's rows. In the same file `pit_latest` picks the latest row with `row_number()` over a `GRAIN` window; `F.max(struct(_d, *values))` is the same ordering (date, then each value, largest first; Spark orders NULL lowest and NaN highest, exactly `desc_nulls_last`), and a partial aggregate shrinks the rows before the exchange instead of sorting every joined row after it. Checked against the old code on random data with NULLs, NaN and date ties: 0 differing rows both ways (60 rows).

### S2-03  A2 DCORE: reduce to account-days before the join with the observations; one aggregate
Files: `a2_locatability/signals.py:158-285` (`_dcore_events` -> `_dcore_days`, `build_dcore_signals`)
Behaviour: none
Change: `_dcore_events` joined every DCORE event (many per account-day: calls, notes, results) to every observation of its account, then four frames read the result: `records` (deceased / skip-trace dates), `days` (per account-day flags), and from `days` `calls_summary` and `last_days` (a `row_number` window). All flags are per (account, day) and independent of the observation, so they are reduced to one row per `(account_id, day)` first (`_dcore_days`), then joined to the observations (day <= observation_date) once. The call test moves into the aggregate expressions (`call & outbound`, `call & contact`) so the non-call days keep only the deceased / skip-trace flags. One window numbers the attempt days newest first and one `groupBy(GRAIN)` yields the summary, the deceased and skip-trace dates, the record marker and the streak counts. `records`, `calls_summary` and `last_days` and two `left_join_all` parts disappear.
